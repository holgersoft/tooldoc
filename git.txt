First time user setup, once per account:
  git config --global user.name "user"
  git config --global user.email "user@host.example.com"
  * To add the host name helps to separate the commits from the different hosts for host specific modifications.
  git config --global alias.st status

Show configuration:
  git config --list

Create an empty Git repository:
  mkdir my_project
  cd my_project
  git init

Create a Git repository from en existing directory:
  cd my_project
  git init
  git add .
  git commit -m "Added initial project data."

Clone an existing repository:
  * Filesystem:
    * Uses hardlinks and direct copy operations, i.e. fast:
      git clone /srv/git/my_project.git [directory]
    * Uses regular data transfer functions, less efficient:
      git clone file:///srv/git/my_project.git [directory]
  * SSH protocol:
    git clone [user@]host:/srv/git/my_project.git [directory]
    git clone ssh://[user@]host[:port]/srv/git/my_project.git [directory]
  * Git protocol:
    git clone git://host.xz[:port]/path/to/repo.git [directory]

Add files, stageing a file:
  git add file...

Show status:
  git status [-s]

Show current hash:
  git rev-parse HEAD

Show local modificatins (that are not staged yet):
  git diff

Undo local modifications:
  git checkout -- file...

Show modifications that are in the staging area, i.e. that will be committed:
  git diff --staged

Unstaging a file:
  git reset HEAD file...

Commit changes:
  git commit [-m "Message."] [file...]
  * This commits the staging area.
  * To commit modified and staged files:
    git commit -a [-m "Message."]
  * To update the previous commit after staging the update:
    git commit --amend
  * To change the previous commit message right after the previous commit:
    git commit --amend [-m "Updated message."]
  * To push the change if it was changed after a previous push (use with care!):
    git push --force-with-lease

Rename a file:
  git mv file_old file_new
  * Git doesn't record renames.
  * This stages the deletion of file_old and the addition of file_new.

Delete files:
  git rm file...

Show history:
  git log [-<number of commits>] [file...]

Show commit details:
  git show <hash>

Undo the last commit, that was not pushed yet:
  git reset --soft HEAD~1

Undo a commit:
  * Find the hash
  git revert <hash>
  * If it is a merge commit and the merge is to be undone:
  git show <hash>
    * First parent hash is previous commit in affected branch, second parent is from branch that was merged
  git revert -m 1 <hash>

Integrate a commit from another branch:
  git cherry-pick <commit>
  * <commit> is one of:
    * sha1 hash, e.g. dae86e1950b1277e545cee180551750029cfe735, dae86e

To get a file from the repository, i.e. an older version:
  git show <HASH>:path/from/repo/root/to/file

Show remote repositories:
  git remote -v

Push changes to upstream repository:
  git push [origin [main]]

Get changes from upstream repository:
  git fetch [origin]
  * Fetches the changes to the local repository but does not merge them into
    the workspace.

Merge upstream changes into workspace (after fetching them):
  git merge [origin/main]
Get changes from upstream repository and merge into workspace:
  git pull

Creating a feature branch:
  * Just create the branch:
    git fetch [origin]
    git branch featureA main
  * Create the branch and switch to it:
    git fetch [origin]
    git checkout -b featureA origin/master

Merging a feature branch into master:
  git fetch origin
  git checkout main
  git merge featureA
  git push origin main
  * Or with rebase:
  git fetch origin
  git checkout main
  git rebase featureA
  git push origin main

Show local branches, i.e. branches that were checked out in the past:
  git branch

Show all available branches:
  git branch -r

Switch to a branch:
  git switch <branch>
  * The original command, which still works, is:
  git checkout <branch>

Switch to a tag:
  * List tags:
  git tag
  * Switch:
  git checkout tags/<tag>

Switch to a commit and create a branch from there:
  git checkout <hash>
  git switch -c new-branch

Add more remote repositories:
  * This adds repositories to the initial "origin".
  git remote add some_name URL

When a branch is created, it will follow the original branch. To change the original branch:
  # Change to branch
  git branch --set-upstream-to origin/<main>

Merge the changes of a merge request into another branch, e.g. into another release branch
  * In Gitlab:
    * Open merge request
    * Go to "Merged by" section
    * Follow the "Cherry-pick" link
    * Select project, branch, and whether to start a new merge request
    * This will create a branch cherry-pick-12345678 with an automatic commit that contains the cherry-picked merge commit. This description of the automatic commit contains merges from the main branch, that are actually not part of the commit. I.e. the patch that was merged, i.e. all changes in the original branch, will be part of the commit.
    * There is no way to create a new branch with the individual commits of the original feature branch cherry-picked
  * On command line
    * It does not work to cherry-pick the merge commit, this will include merges from the main branch into the original feature branch
    * The commits of the original feature branch need to be cherry-picked one-by-one into a new feature branch that then is turned into a merge request
    * Create a new feature branch from the branch the changes are merged to the usual way
    * Option 1:
      * Find commit the feature branch is based on (A), last commit in feature branch (B), and last commit in main branch before the merge (C)
      git log A..B --not C
    * Option 2:
      * Open the Gitlab merge request Commits page and cherry pick from bottom to top
      * On Linux and a standard terminal one can copy+paste "git cherry-pick " by selecting it and paste with middle mouse button, the commit hash can be copied by clicking on the copy widget next to the hash and paste with Ctrl+Shift+V in the terminal (or terminal context menu)
    * Cherry pick all commits, but not "Merge ... into <feature branch>"
    * Push
    * Create merge request, compare with original merge request
    

Ignoring files:
  * Edit .gitignore in working copy toplevel directory (or subdirectories)
# ignore all .a files
*.a
# but do track lib.a, even though you're ignoring .a files above
!lib.a
# only ignore the TODO file in the current directory, not subdir/TODO
/TODO
# ignore all files in the build/ directory
build/
# ignore doc/notes.txt, but not doc/server/arch.txt
doc/*.txt
# ignore all .pdf files in the doc/ directory and any of its subdirectories
doc/**/*.pdf

Setting up an SSH based repository:
  * Optionally create an DNS alias gitserver that points to the server machine.
  * Create an empty repository or clone an existing repository.
    Directory ends with suffix .git:
    git init --bare /data/srv/git/my_project.git
    git clone --bare /path/to/my_project /data/srv/git/my_project.git
  * Optionally copy repository to SSH server if it was not created on the server:
    scp -rp path/to/my_project.git [user@]host:/data/srv/git/
  * Clone remote repository:
    git clone [user@]host:/data/srv/git/my_project.git
  * Optionally set group write permissions, if needed:
    ssh [user@]host
    cd /data/srv/git/my_project.git
    git init --bare --shared

  * Or create repository locally and push to server:
    cd my_project
    git init
    git remote add origin [user@]host:/data/srv/git/my_project.git
    git push origin main


Modules
-------
Show sub-module status:
  git submodule status

Checkout all sub-modules, after initial clone:
  git submodule update --init --recursive

Checkout a specific sub-module:
  git submodule update --init <submodule>

Change branch of a sub-module:
  git submodule set-branch -b v1.0.0 <submodule>


Visual Studio Code
------------------
  * To commit lines in a file instead the complete file:
    * Open Changes (top right), or context menu Open Change -> Open Line Changes with Previous Revision
    * Select lines that are to be committed, either all or ranges with Alt+select (or Ctrl+select after Selection->Switch to Ctrl+Clock for Multi-Cursor)
    * Stage Selected Ranges (context menu)
    * Commit staged changes
